# Video Studio - standing agent instructions

- This repository produces many kinds of videos; no hard-coded video genre, renderer, TTS provider or machine-specific path.
- Invoke the matching `video-*` skill for the task. The skills ship in `skills/` and are registered profile-wide by the bundle, so they also load in a session opened outside this checkout. `video-produce` is the accountable coordinator when the user wants a full deliverable.
- Resolve `scripts/` against the code root and `projects/`, `library/`, `.cache/` against the data root printed in the skill header. The data root defaults to the session workspace; explicit settings may override it. Run the code root's `scripts/studio-root.mjs` from the workspace to print effective roots; `scripts/init-workspace.mjs` initializes the data root idempotently.
- Accept natural-language requests. Extract facts from the user files and existing project settings rather than demand an intake form. Record the production mode (`narrated`, `silent`, `text-only`, `mixed`); never create fake narration for a silent or text-only film.
- Draft narration and validate factual/math claims BEFORE TTS or scene coding; narration is independent of individual animation beats.
- Build the through-line map before prose: central question, promise, audience, and every section's purpose, connection, why it is here and the takeaway.
- Narration G0 has two gates. Mechanical integrity checks schemas, hashes, references, claim locations, through-line/section coverage, review evidence locations and segment coverage. The editorial gate checks that the review is evidence-based and complete. Neither deterministic check proves mathematical truth; never say it does.
- A narration PASS requires `throughline-map.json`, a v2 `claim-check.json` (verified claims need evidence/derivation and a real narration location), and a v2 `narration-review.json` with all eight criteria pass, cited evidence covering every section, no unresolved blocking findings, and the current SHA-256. High-risk or quality-sensitive narration also needs one genuinely independent review pass (prefer an existing DSH subagent, fresh context, no scenes/TTS/render).
- Never synthesize, storyboard or code scenes from a draft, stale hash or blocked review. Run `node scripts/validate-narration.mjs <episode-dir>` before audio. Use `scripts/revise-narration.mjs` for an intentional revision; it archives the old script, blocks the review and invalidates downstream segments. Never hand-edit a frozen narration or overwrite a released master without authorization.
- `spokenText` may only describe pronunciation through declared overrides with provenance and justification. It must never change a number, operator, sign, quantity or mathematical claim; `trừ` -> `cộng` is a blocker even if a review says otherwise.
- Reuse approved templates first (A), copy/patch an approved scene second (B), code new scenes last (C). Keep an explicit `reuseFrom` when applicable. Promote only QA-PASS scenes through `scripts/promote-scene.mjs`; never overwrite an accepted catalog id.
- Use the configured DSH `video-scene-worker` preset for at most two independent C scenes in parallel. Nesting depth and concurrency are different limits. Do not start QA agents per scene; code-based QA is the default.
- Workers can write only inside their assigned episode `work/<task-id>/` allowlist. Main agent owns global timeline, assets manifest, narration and library promotion. Validate every worker result with `scripts/validate-workers.mjs`; prompt instructions are not filesystem security enforcement.
- Before batch speech, verify the actual provider/device, voice reference and a short synthesis sample with `scripts/audio-preflight.mjs`. `nvidia-smi` proves hardware, not provider readiness. Use bounded TTS/ASR jobs with explicit timeout/retries, and never silently fall back from GPU to a slow CPU backend.
- Select render/audio backends from preflight checks and project requirements. Do not use HyperFrames, Remotion, OmniVoice or any other specific engine unless available and appropriate.
- Do not install packages, use paid external services, or overwrite/delete a released master without explicit user authorization.
- Preserve accepted scene sources, source attribution, cached narration and master output. Work directories may be cleaned only after safe QA retention and explicit approval.
- `--lint` is work in progress. Release only through `node scripts/validate-episode.mjs <episode> --release`, which requires a real verified master, QA artifacts, scene QA, narration G0 for narrated/mixed, audio/timeline consistency and no unresolved stale markers. A fresh episode is INCOMPLETE, never PASS.
- Measure real elapsed time, model/tool usage, cached tokens, retries, failed jobs, worker concurrency and image reads with `scripts/collect-metrics.mjs` from DSH session logs. Never label theoretical savings or manually estimated numbers as measured.
- Deliver the requested master file or state precisely which prerequisite/failed gate blocked delivery, and record remaining unknowns as unknowns.
