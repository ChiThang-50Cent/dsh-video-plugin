# Video Studio — standing agent instructions

## Scope & roots

Do not hard-code genres, renderers, TTS providers or machine paths. Invoke the matching `video-*` skill; `video-produce` coordinates full deliverables. Skills in `skills/` load profile-wide, even outside this checkout.

Resolve `scripts/` against the code root and `projects/`, `library/`, `.cache/` against the data root in the skill header. The data root defaults to the workspace unless overridden. From the workspace, run the code root's `node scripts/studio-root.mjs` for effective roots; `node scripts/init-workspace.mjs` initializes the data root idempotently.

## Workflow

1. Accept natural-language requests; extract facts from user files and project settings, not an intake form. Record mode: `narrated`, `silent`, `text-only` or `mixed`. Never fake narration for silent or text-only films.
2. Before prose, map the central question, promise, audience, and each section's purpose, connection, reason and takeaway. Draft narration independently of animation beats; validate factual/math claims before TTS or scene coding.
3. Pass narration G0 before audio, storyboarding or scene coding. For revisions use `node scripts/revise-narration.mjs <episode-dir> --from <new-narration.md> --reason "<why>"`: it archives the old script, blocks review and invalidates downstream segments. Never hand-edit frozen narration. For high-risk or quality-sensitive narration, obtain a genuinely independent review, preferably an existing DSH subagent in fresh context, without scenes, TTS or render.
4. Pass audio preflight before batch speech. Bound TTS/ASR jobs with explicit timeouts and retries; never silently fall back from GPU to a slow CPU backend. For OmniVoice, synthesize with `node scripts/synthesize-narration.mjs` (one model load, resumable) rather than one process per segment.
5. Storyboard, then reuse in order: approved template (A), copy/patch approved scene (B), new code (C). Keep `reuseFrom` when applicable. Promote only QA-PASS scenes with `node scripts/promote-scene.mjs <catalog-id> <scene-code> <preview> <qa-report>`; never overwrite an accepted catalog id.
6. Use DSH `video-scene-worker` for at most two independent C scenes concurrently; depth is not concurrency. Generate briefs with `scripts/worker-brief.mjs` and dispatch verbatim. Workers write only in their episode `work/<task-id>/` allowlist; the main agent owns the timeline, assets manifest, narration and library promotion. Validate worker plans and every result below. Prompts are not filesystem security enforcement. Default to code-based QA, not a QA agent per scene.
7. Run `node scripts/preflight.mjs`; use Skia for supported 2D code animation when it passes. Other render/audio backends must be verified and appropriate. Scenes take every colour and font from `api.theme`; the look lives in `library/visual-styles/<id>/` selected by `production.json`/`project.json` `visualStyle`. To change the look, create/edit/select a style package (`scripts/new-visual-style.mjs`, `scripts/extract-style-refs.mjs`), never restyle scenes by hand. Render an episode with one blocking `node scripts/render-episode.mjs <episode> --out <new-path> --json` (parallel, cached, loudness-normalized). Render, QA and release below.
8. Measure elapsed time, model/tool usage, cached tokens, retries, failed jobs, worker concurrency and image reads from DSH logs with `node scripts/collect-metrics.mjs --episode <episode-dir> --json`. Never label estimates or theoretical savings as measured. Deliver the master or state the exact blocking prerequisite or failed gate; record unknowns.

## Gates

- **Narration G0:** `node scripts/validate-narration.mjs <episode-dir>` must pass before audio. Its mechanical integrity and editorial gates check structural consistency and evidence-based review respectively; neither proves mathematical truth. A PASS requires `throughline-map.json`, v2 `claim-check.json` with evidence/derivation and a real narration location for verified claims, and v2 `narration-review.json` with all eight criteria passing, cited evidence covering every section, no unresolved blocking findings and the current SHA-256. Never synthesize, storyboard or code scenes from a draft, stale hash or blocked review. `spokenText` may only describe pronunciation using declared overrides with provenance and justification; it must never change a number, operator, sign, quantity or mathematical claim. `trừ` → `cộng` blocks even if a review says otherwise.
- **Audio:** `node scripts/audio-preflight.mjs --provider <provider> [--provider-command <path>] --voice-reference <voice-file> --synthesize-sample --require-gpu --json` must pass for the actual provider, device and voice before batch speech; drop `--require-gpu` only for a provider that is CPU or network by design, and say so. `nvidia-smi` shows hardware, not provider readiness.
- **Workers:** `node scripts/validate-workers.mjs plan <plan.json> --max-concurrency 2 --max-depth 1` must pass before dispatch. Before a wave, run `node scripts/validate-workers.mjs snapshot <episode> --task <wave-id>` and keep its SHA-256 outside worker control; after the wave, `node scripts/validate-workers.mjs wave <episode> --baseline <episode>/qa/worker-baselines/<wave-id>.json --baseline-sha256 <sha256> --result <result.json>... --allow 'work/<task-id>/**'...` must pass before integration.
- **Release:** `node scripts/validate-episode.mjs <episode> --release` must pass. It requires a real verified master, QA artifacts with loudness PASS, scene QA for every scene recording the current `styleSha256` (and `narrationSha256` for narrated/mixed), narration G0 for narrated/mixed, audio/timeline consistency and no unresolved stale markers. `--lint` is work in progress; a fresh episode is INCOMPLETE, never PASS.

## Hard limits

Do not install packages, use paid external services, or overwrite/delete a released master without explicit user authorization. Preserve accepted scene sources, source attribution, cached narration and master output; clean work directories only after safe QA retention and explicit approval.
